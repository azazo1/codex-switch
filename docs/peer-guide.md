# 节点转发指南

可以把另一台 Codex Switch 做成上游. 本机选中它后, 客户端请求原样转到对端, 由对端自己的调度组, OAuth 和 API Key 继续处理.

发现只负责找地址, 不负责信任. 真正能转发前必须完成双向配对.

## 两个端口

本地客户端继续使用明文代理口, 默认 `127.0.0.1:15721`.

节点之间使用独立 TLS 口, 默认 `0.0.0.0:15722`. 这个口只接受已配对节点的 mTLS, 不使用本地访问 key.

不要把明文代理口改成 `0.0.0.0` 来代替节点口.

## 身份

每个节点首次启动会生成:

- 持久 `node_id`
- Ed25519 身份密钥
- 短指纹, 形如 `CS-A1B2-C3D4`

指纹来自公钥的 SHA-256 前 4 字节. 配对前应对照两边界面上的指纹.

私钥明文保存在本地 SQLite 的 `settings` 表中, 保护级别和现有 API Key 相同.

## 配对

打开 `节点` 页签:

1. 在对端 `节点` 页点击 `启动` 监听节点请求, 并启动代理服务.
2. 本机填写 `host:port` 或 `https://host:port`, 可选填写对端指纹.
3. 点击 `配对`. 对端会出现待确认请求.
4. 对端核对指纹后点 `接受`.

发现列表里的节点同样需要手动点 `配对`. 发现到不等于已经信任.

取消配对: 删除对应的 `PeerNode` 上游. 对端再用旧证书连接会被拒绝.

## 发现

### 直连

在 `节点` 页填写地址即可. 地址只是配对入口, 仍要确认指纹.

### mDNS

开启 `启用 mDNS` 后, 同局域网可以零配置看到其他 Codex Switch. 服务名为 `_codex-switch._tcp.local.`. TXT 只包含 `id`, `fp`, `name`, `ver`.

mDNS 依赖组播, 跨 VLAN 或容器网络可能不可见.

### lnd

`lnd-core` 是中心 HTTP 注册表, 不是 mDNS. Codex Switch 只做 client, 不会在本机嵌入 `lnd-server`.

在 `节点` 页勾选 `启用 LND`, 再打开 `LND 设置` 填写:

- lnd server URL, 例如 `http://192.168.1.2:8765`
- bearer token
- 可选 discovery domain

点 `保存` 后重新启动服务才会生效. 点 `取消` 会丢弃弹窗中的未保存修改.

service type 为 `_codex-switch._tcp`. lnd-server 能看到指纹和地址, 看不到私钥, 也不能代替配对.

## 转发行为

`PeerNode` 上游会:

- 跳过协议转换, compact 清洗, OAuth body 改写和 server_tool 过滤
- 使用钉扎证书的 mTLS 客户端
- 带上 hop 头 `x-codex-switch-hop`
- 不转发本机本地访问 key

对端收到后按自己的调度组继续处理. 环路或超过 `peer_max_hops` (默认 4) 会返回 `502`.

节点上游不查询余额, 也不在本机跑 cache keepalive. 这些仍由对端自己处理.

## 安全边界

- 发现不等于信任.
- 节点口是 TLS, 本地客户端口仍是明文 HTTP.
- 配对前的 TOFU 握手会展示指纹, 必须人工确认.
- 未配对证书即使能连上节点口, 也不能转发模型请求.
- lnd-server token 只用于发现注册, 不用于模型转发.
