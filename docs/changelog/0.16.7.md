# Codex Switch v0.16.7

Date: 2026-09-29

本版本给临时访问 key 加上模型范围限制, 并移除两个会把请求改坏的上游开关.

## Highlights

- 临时访问 key 可以限制可用模型: 填 `gpt-*` 这类 glob 模式后, key 只能请求匹配的模型, `/v1/models` 也只列出匹配项.
- 移除 `工具输出紧跟调用`. 实测客户端原始的并行工具调用顺序本来会被上游接受, 是重排把它改成了 `400`.
- 移除补占位思维链. 占位项落在两条并行调用之间时, 上游会判定前一个调用没有输出, 返回 `400 No tool output found`.

## Breaking Changes

- 上游编辑器的 `工具输出紧跟调用` 开关被移除, 上游表的 `reorder_tool_outputs` 列由迁移 `33` 删除. 影响范围: 在 v0.16.6 里开启过该开关的上游. 迁移方式: 不需要手动操作, 转发行为回到不重排.
- 开启 `还原 reasoning_text` 的上游不再为缺少思维链的工具调用回合补占位项. 迁移方式: 不需要手动操作. 该开关现在只做还原, 即保留客户端带上来的思维链, 不再凭空造项.

## Upgrade Notes

1. 升级会自动执行数据库迁移 `32` 和 `33`: 临时访问 key 表补 `model_patterns` 列 (默认空, 表示不限制), 上游表删掉 `reorder_tool_outputs` 列. 没有降级 migration.
2. 已有临时 key 的模型范围默认为空, 行为与升级前一致. 需要限制时在临时 key 页面勾选 `限制模型` 并填写模式, 多个模式用逗号分隔.
3. 模型范围在新请求上生效: 请求体的模型不匹配任何模式时返回 `403`; 请求体省略模型字段时同样返回 `403`, 不能用省略字段的方式绕过.
4. 升级后可在仪表盘确认版本号, 并在上游编辑器确认 `工具输出紧跟调用` 已不再出现.

## Features

- 临时访问 key: 新增模型范围限制, 支持一个或多个 glob 模式, 例如 `gpt-*` 或 `qwen3-coder`. 临时 key 页面新增 `限制模型` 复选框与 `模型` 列, 列表里可以一眼看出哪些 key 受限.
- 代理: 受限 key 的请求体模型不匹配任何模式时返回 `403`; 请求体没有模型字段时同样拒绝.
- 代理: `/v1/models` 与 `/v1/models/<id>` 走同一套模式过滤. Anthropic 分页仍返回 `has_more` / `first_id` / `last_id`, 被过滤掉的模型沿用原有的 `404`, 不暴露未授权模型的存在.

## Bug Fixes

- Responses 中转: 移除转发前的工具输出重排. 实测同一段历史, 客户端排成 `call, call, output, output` 时上游返回 `200`, 重排成 `call, output, call, output` 后返回 `400 The reasoning_text in the thinking mode must be passed back to the API`. 并行工具调用轮次较多的会话因此更容易中招.
- Responses 中转: 移除为缺少思维链的调用步补占位 reasoning 项的逻辑. 上游按 `reasoning` 项切分回合, 占位项落在两条并行调用之间时, 前一个调用所属的回合被提前关掉, 它的输出落到回合外, 上游返回 `400 No tool output found for tool call ...`, 之后每轮重放同一段历史都失败.
- 上游编辑器: 更正 `还原 reasoning_text` 的说明文字. 该开关只在 `content` 与 `summary` 之间取舍思维链 (前者留在上下文并计入输入 token, 后者被 DeepSeek 官方忽略), 上面两条 `400` 都不是它造成的, 它也修不了.
