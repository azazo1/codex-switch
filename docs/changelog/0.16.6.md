# Codex Switch v0.16.6

Date: 2026-09-28

本版本给 Responses 中转上游新增 `工具输出紧跟调用` 开关, 并修复 `还原 reasoning_text` 在多轮工具调用历史下的占位补全和上游编辑器的布局问题.

## Highlights

- 上游编辑器新增 `工具输出紧跟调用`: 客户端把并行调用的输出批量排在所有调用之后时, 转发前先把每条输出挪到自己的调用后面, 避免 DeepSeek 官方返回 `400 No tool output found for tool call ...` 且会话无法继续.
- `还原 reasoning_text` 的占位补全改为逐个工具调用判断: 历史里只有最新一轮带思维链时, 更早的调用轮也能补上占位项, 不再触发 `400 The reasoning_text in the thinking mode must be passed back to the API`.
- `编辑上游` 窗口默认 620x560 且不会超出应用窗口, 表单过长时内部滚动, 保存 / 取消 / 导出按钮固定在底部.

## Upgrade Notes

1. 升级会自动执行数据库迁移 `31`: 上游表补 `reorder_tool_outputs` 列 (默认关闭). 没有降级 migration.
2. `工具输出紧跟调用` 默认关闭, 仅对 Responses 中转上游生效; Codex OAuth 和节点上游按 `call_id` 配对输出, 不受该开关影响.
3. 升级后可在仪表盘确认版本号; 打开上游编辑器可以看到开关换行排布, 表单变长时出现内部滚动条.

## Features

- 上游编辑器: Responses 中转上游新增 `工具输出紧跟调用`. 开启后转发前把每条 `function_call_output` 挪到自己的 `function_call` 之后, 被隔开的 developer 消息或 reasoning 项推到输出后面; 已经相邻的项保持不动, 没有输出的调用不合成输出, 没有需要挪动的项时请求原样转发. 每个请求在日志里记录挪动的条数, 排查时可对比 `codex-switch-proxy.log` 中 `client_request` 与 `upstream_request` 两阶段.

## Bug Fixes

- Responses 中转: `还原 reasoning_text` 的占位补全不再要求整段历史已有 reasoning 项, 改为逐个工具调用判断, 只在调用前缺少 reasoning 项时补占位, 已有思维链的轮次保持原样. 修复历史里较早的调用轮由其他上游生成而没有思维链时, DeepSeek 思考模式返回 400 的问题.
- 界面: `编辑上游` 窗口默认 620x560, 大小限制在应用窗口可见区域内 (最小 360x240); 表单在垂直滚动区内滚动, 保存 / 取消 / 导出按钮固定在底部, 表单再长也不会把按钮顶出窗口.
- 界面: 认证方式单选与四个开关分成两行, 开关行自动换行, 表单不再撑破窗口宽度.
- 界面: 上游列表 Base URL 列按内容取宽 (上限 480px), 长链接保留头部省略号, 悬停显示完整值.
