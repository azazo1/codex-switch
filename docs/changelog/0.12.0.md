# Codex Switch v0.12.0

Date: 2026-08-28

本版本新增可信的 Codex Switch 节点转发: 可以把另一台已配对节点当成上游, 用独立 mTLS 口转发全部流量. 同时保留非 v1 的 API 前缀, 并修复推理流和工具结果中的媒体清洗问题.

## Highlights

- 可以把另一台 Codex Switch 配成 `PeerNode` 上游, 确认指纹后再用 mTLS 原样转发请求.
- 支持 IP 直连, mDNS 和 lnd-core 发现节点, 发现不等于信任, 必须手动配对.
- 节点监听和本地明文代理口分开, 可独立启动或停止.
- 保留上游 Base URL 中的 `/vN` 前缀, 并兼容客户端发来的 `/v4/chat/completion` 一类路径.
- Chat 上游的 reasoning 会按 Responses summary delta 转发给客户端.

## Breaking Changes

- 节点之间不再走本地明文代理口. 迁移方式: 在 `节点` 页启动 `监听节点请求`, 默认 TLS 口为 `0.0.0.0:15722`.
- 发现到的节点不会自动获得转发权限. 迁移方式: 对照双方指纹后完成配对, 再把该节点加入调度组.

## Upgrade Notes

1. 升级会写入节点身份, 配对和发现相关设置, 现有数据库会自动迁移.
2. 需要接收其他节点流量时, 在 `节点` 页填写地址并点击 `启动`. 仅把流量转到对端时, 本机可以不听节点口.
3. 勾选 `启用 mDNS` 或 `启用 LND` 后, 需要重启节点监听才会生效. LND 只做 client, 需自行提供 lnd-server.
4. 换局域网后可用新 IP 再配对一次, 或编辑 `PeerNode` 上游地址; 同一 `node_id` 不会重复创建上游.
5. 升级后对照节点页指纹完成配对, 再用一次模型请求确认转发成功.

## Features

- 每个节点生成持久 Ed25519 身份和短指纹, 配对后钉扎证书, 未配对证书不能转发模型请求.
- `节点` 页可查看本机指纹, 直连配对, 确认入站请求, 以及查看已配对和发现到的节点.
- 节点发现提供独立的 mDNS 和 LND 开关, LND 的 server, token 和 domain 在保存/取消弹窗中填写.
- macOS 和 Linux 托盘标题可显示一或两行指标.

## Bug Fixes

- 修复节点配对 mTLS 握手失败, 界面停在正在配对却没有任何结果的问题.
- 修复 mDNS 浏览在第一次超时后退出, 导致发现列表一直为空的问题.
- 修复编辑 `PeerNode` 上游地址后, 已配对列表仍显示旧 IP 的问题.
- 修复 Chat 推理内容无法作为 Responses summary 流式转出的问题.
- 修复工具调用结果里内嵌的媒体仍进入文本模型的问题.
- 修复模型映射输入框不会随内容变宽, 以及隐藏窗口占位几何被写回窗口状态的问题.
- Windows 调试构建保留控制台, 便于 Ctrl+C 结束 `cargo run`.
