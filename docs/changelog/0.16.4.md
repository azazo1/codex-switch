# Codex Switch v0.16.4

Date: 2026-09-22

本版本修复活跃连接页实时输出窗口在思考型模型上看不到内容的问题, 并让调试日志开关真正生效.

## Highlights

- 实时输出窗口能显示思考型模型的思考内容, 例如 deepseek v4.1 flash 这类把增量放在 `choices[].delta.reasoning` 的上游, 之前整个思考阶段都停在 `等待输出`.
- 窗口右端不再丢字: 之前按估算宽度取窗口, 中文等宽字符会被截掉最右侧也就是最新的字符.
- `启用完整调试日志` 开关恢复作用, 打开后主日志记录 `codex_switch` 全量 trace, 模型调用日志只记录 `codex_switch::proxy` 和 `tower_http`, 两个文件不再雷同.

## Upgrade Notes

1. 升级不涉及数据库迁移, 现有上游, 日志, 设置和计价脚本保持不变.
2. 依赖中新增 `tracing-core`, 使用 lockfile 构建时无需其他操作.
3. 升级后可在仪表盘确认版本号, 并在活跃连接页对照客户端输出确认实时输出窗口的内容与末端字符.

## Bug Fixes

- 活跃连接: 实时文本提取补上 `choices[].delta.reasoning`, 并在缺少该字段时回退到 `reasoning_details[0].text`. 此前只识别 `content` 和 `reasoning_content`, 思考阶段窗口一直显示 `等待输出`, 直到正文开始才有内容, 看起来像输出滞后.
- 活跃连接: 输出窗口改为按真实字形宽度收缩, 保证右端始终是最新收到的字符. 此前用固定字符宽度估算, 宽字符 (中文等) 超出控件宽度后会被从右侧截断.
- 调试日志: `启用完整调试日志` 现在能真正提高日志级别. 此前 per-layer filter 因为包在 reload 层里而失效, 主日志与模型调用日志会记录同一批事件, 且运行期切换级别后没有重建 interest cache, 全局最高级别停在 `INFO`, `DEBUG` 和 `TRACE` 事件不会产生.
- 调试日志: 轮转设置变化时改为替换共享写入句柄, 不再重建日志层, 并在切换时记录当前生效的两个过滤器.
