# 日志使用指南

Codex Switch 有两类日志:

- `日志` 页面保存代理请求记录, 用于查看用量, 状态和性能.
- tracing 运行日志记录程序阶段和错误, 用于诊断应用本身.

清理请求日志不会删除 tracing 运行日志.

## 请求日志字段

| 字段 | 说明 |
| --- | --- |
| 上游 | 实际使用的上游, 悬浮可查看状态和错误 |
| 模型 | 客户端模型名, 请求失败时附带错误标记 |
| 推理强度 | 请求中的 reasoning effort |
| TOKEN | 输入, 缓存输入, 缓存写入, 输出和总 token |
| 费用 | 写入日志时根据价格缓存或计价脚本计算的 USD 估算, 详见[费用估算与计价脚本](pricing-guide.md) |
| 首 TOKEN | 流式响应收到首段数据前的时间 |
| 耗时 | 请求从进入代理到结束的总时间 |
| 时间 | 请求完成时间, 按本地时区显示 |

悬浮上游或模型可以查看 endpoint, status 和错误文本. 点击 token 数字可以切换简写和精确数字.

请求日志不保存 prompt 或完整响应正文. 它会保存模型名, 上游, endpoint, 状态码, token, 费用估算, 耗时和错误文本等元数据.

一行日志代表一次上游尝试或一次内部缓存保持请求, 不一定代表一个独立客户端请求. 失败切换可能为一个客户端请求产生多行日志, `/internal/cache_keepalive` 也会计入仪表盘请求数和用量汇总.

## 分页

每页可以显示 `10`, `20`, `50` 或 `100` 条记录. 切换每页数量会回到第一页. 顶部会显示当前结果范围和筛选后的总条数.

## 筛选

点击 `筛选日志` 可以组合以下条件:

- 模型, 支持 `*` 和 `?` 通配符.
- 上游, 推理强度和 endpoint.
- 状态码类别或自定义范围.
- 日志完成时间范围, 界面使用开始和结束两个边界输入.
- USD 费用范围.
- 总耗时和首 token 延迟范围.
- 输入, 输出, 缓存输入, 缓存写入和总 token 范围.

Token 范围支持 `K`, `M`, `B` 和小数, 例如 `1.5M`. 最小值大于最大值或输入无法解析时, 状态栏会显示筛选错误.

部分下拉候选从当前页记录生成. 较早记录的模型, endpoint 或推理强度可能不在候选中, 其中模型字段可以直接输入通配符.

## 清理

点击 `清理日志` 后可以选择:

| 策略 | 实际行为 |
| --- | --- |
| 保留一天 | 删除早于当前时间 1 天的记录 |
| 保留一周 | 删除早于当前时间 7 天的记录 |
| 保留一个月 | 删除早于当前时间 30 天的记录 |
| 保留一年 | 删除早于当前时间 365 天的记录 |
| 保留指定条数 | 只保留最新 N 条 |
| 只清理失败请求 | 删除 `status >= 400` 的记录 |

清理后会从剩余请求重新构建用量汇总. 因此仪表盘的历史请求数, token 和估算费用也会下降. 当前没有请求日志导出或自动保留周期.

删除记录不会立即缩小 SQLite 主文件. 空闲页面可以在仪表盘数据库区域观察.

## 时间和费用边界

日志列表时间使用本地时区. 仪表盘的 `今日` 汇总当前按 UTC 日期计算, 在本地午夜附近可能与日志列表的自然日范围不同.

单条日志费用使用请求完成时的价格缓存和当时的全局/上游脚本链路. 仪表盘总估算, 今日估算和按上游估算对这些已写入费用求和. 后续刷新模型价格或修改脚本不会回写旧日志费用, 也不会改仪表盘合计.

## Tracing 运行日志

普通模式会在数据目录写入两个滚动日志文件:

- `codex-switch.log` 主日志, 记录应用运行日志 (界面, 存储, 保活调度, 节点发现等).
- `codex-switch-proxy.log` 模型调用日志, 记录代理转发, 路由, 重试和协议转换. 默认只记录 info 级及以上, 开启完整调试日志后记录完整 tracing 和代理 body.

两个文件都按每日和配置的单文件大小轮转, 并共享同一份轮转文件数配置.

仪表盘的 `调试日志` 区域可以开启完整调试日志, 也可以调整轮转大小和轮转文件数. 非 Windows 仍会保留标准错误输出.

## 网络请求 HAR

开启完整调试日志后, 所有出站 HTTP 请求会完整记录到数据目录的 `codex-switch-network.har` (HAR 1.2 格式), 可直接用 Chrome DevTools 或其他 HAR 查看工具打开. 覆盖范围包括代理转发 (流式和非流式), `/v1/models` 查询, 余额查询, 配额查询, 缓存保活, 价格和汇率获取, OAuth 以及节点间请求.

每个 entry 记录请求方法, URL, 请求头, 请求体, 响应状态, 响应头, 响应体和耗时. 单个请求或响应体超过 10 MB 会截断并标记 `_truncated`, 请求失败时标记 `_error`. Authorization, API Key 和 Cookie 类请求头会脱敏为 `[REDACTED]`, OAuth 认证域名 (`auth.openai.com`) 的请求体和响应体也整体脱敏为 `[REDACTED]`, 其余内容包含完整 prompt 和模型输出, 不要公开 HAR 文件.

HAR 文件与主日志共享轮转大小和轮转文件数配置, 轮转分段的文件名形如 `codex-switch-network.1.har`. 文件采用流式追加写入, 进程在任意时刻退出后文件仍是合法的 HAR; 仅当上次写入中途崩溃时, 残留文件会原样轮转保留.

关闭完整调试日志时不产生任何 HAR 记录.

可以在启动进程前设置 `RUST_LOG` 调整日志级别, 也可以设置 `CODEX_SWITCH_LOG_FILE` 和 `CODEX_SWITCH_LOG_BODIES` 覆盖 GUI 设置. 指定 `CODEX_SWITCH_LOG_FILE` 时主日志写入该文件, 模型调用日志写入同目录的 `<名称>-proxy.log` 并按同样方式覆盖, 网络请求追加写入同目录的 `<名称>-network.har`, `RUST_LOG` 作用于主日志. 数据目录位置见[存储与备份指南](storage-guide.md).
